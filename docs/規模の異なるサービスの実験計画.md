# サービス規模と共通登録者数を同時に変える実験計画

2026年11月25日。新規サービスの架空登録者1万人から無作為に10人を非復元抽出し、10人全員を正しく照合できる確率が80%になる境界を調べる。過去の各社では1回ずつ、登録者全員から決められた件数を等確率で非復元抽出する。会社間の事故は独立とする。共通登録者はどのサービスでも本人に一意の同じメールを使い、過去の漏えい行と本人の対応がすべて分かる。過去に1度も現れない対象者は保留となり、その回は全員正答に数えない。[前回の実験](多サービス実験結果.md)

## サービスの規模と共通登録者数

AとBは交互に加える2種類の会社を表す。ペアごとの延べ登録者数を2,000人にそろえ、名簿の規模と、そのうち何人が新規サービスにも登録しているかを別々に指定する。各ペアの共通人数の合計は延べ人数である。

| 条件 | A・Bの登録者数 | A・Bと新規サービスの共通人数 |
|---|---:|---:|
| 前回の基準 | 1,000・1,000 | 1,000・1,000 |
| 大小の会社がそれぞれ全員を共有 | 500・1,500 | 500・1,500 |
| 同規模で各社500人を共有 | 1,000・1,000 | 500・500 |
| 大小で各社500人を共有 | 750・1,250 | 500・500 |
| 大きい会社で多く共有 | 750・1,250 | 250・750 |
| 小さい会社で多く共有 | 750・1,250 | 750・250 |
| 同規模で共通人数にだけ差をつける | 1,000・1,000 | 250・750 と 750・250 の2条件 |
| 大小で各社250人を共有 | 750・1,250 | 250・250 |

各社の漏えい人数は登録者数の12%、24%、100%と、一律120人、一律240人の5条件とする。どの名簿でも端数は生じない。1ペアが漏えいする合計人数は、12%と一律120人では240人、24%と一律240人では480人である。

## 三つの境界

1. **同じ群を繰り返し各社に割り当てた場合の最小社数。** 新規登録者1万人を各社の共通人数ずつ連続した群に区切り、一巡したら同じ順で同じ群に戻る。各社の残りの枠は新規サービスの対象外で埋める。会社を1社加えたとき、それまでの登録や履歴は保持する。1〜2,000社の整数で80%を初めて超えるか等しくなる社数を計算し、その1社手前と到達点の確率を記録する。Aから始める場合とBから始める場合を両方調べる。
2. **登録配置を観測できない場合の複数登録者数。** 過去2社以上に登録した新規サービスの実人数を $D$ とする。10、20、50、100、140、200、280、299、300、500、600、1,000社について、Aから始め、各設計で実現可能な $D$ の全整数を調べる。12%、24%、100%の各漏えい率で、どの配置でも未達、配置次第で到達、どの配置でも到達の3区分を求める。不等式の精度が足りない点は判定保留とする。
3. **各社が登録者を独立に選ぶ場合の最小共通人数。** 750人と1,250人の会社を半々にする。各社は共通人数だけを新規登録者1万人から独立に非復元抽出し、その後に名簿全体から漏えいする。140、200、300、500、1,000社に固定し、共通人数をA・Bで $t:t$、$t:3t$、$3t:t$ とする。各社の定員まで整数 $t$ を動かし、名簿と事故の両方で平均した全員正答確率が初めて80%以上になる人数を求める。この条件では $D$ 自体も抽選で変わる。

## 反復と検算

循環配置では、共通登録者と同じ群にいる新規対象者が同時に抽出される確率を組合せで数える。独立に選ぶ名簿についても、会社の登録枠と漏えい枠の両方を有限集団からの抽出として扱う。80%との比較は表示用の丸め前に行う。小さい名簿で全抽選を直接列挙し、前回と同じ名簿条件では前回の境界も照合する。

循環配置のうち「大小の会社がそれぞれ全員を共有」「大小で各社500人を共有」「大きい会社で多く共有」「小さい会社で多く共有」をAから始める。12%、24%、一律120人、一律240人のそれぞれで、計算した境界の直前と到達点を各20万回抽選する。シードは12,000,000〜12,199,999で、条件間では同じ範囲を使う。合計32点を事前に定め、点ごとの両側95% Wilson信頼区間を記録する。最小社数の判定には組合せによる計算を使う。

## 結果を受けて加えた分析

一律120人・240人の条件で循環配置の順番を変えるだけでは説明できない境界の差が出たため、小規模社から始める3配分について、各人の登録先を自由に選べる場合の最小到達社数も調べる。どの配置でも未達になる社数の上限と、到達する具体的な登録配置を組み合わせて判定する。
