# 情報漏えいと再識別の模擬実験

過去の漏えいで「このメールアドレスは誰のものか」が分かっていたら、別の漏えいで何が新たに分かるでしょうか。講義で扱った名簿の照合をもとに、**過去に本人が判明した記録と、新たに漏れた架空の健診判定を結び付ける実験**を実装しました。Rustで人口と漏えい事故を生成し、DuckDBで各行が誰の記録かを予測し、正解表で採点します。過去のサービス数を増やす追加実験では、Rubyで全員を正しく特定できる確率を厳密に計算しました。[実験計画](docs/実験計画.md)

## Rustで架空の人口名簿を作る

全国規模の実験では、公的統計をもとに15〜64歳の架空の人口7,332万2,000人を生成しました。年齢階級に応じて生年月日と免許保有の有無を決め、同居する人には同じ世帯住所コードを割り当てます。よく見られる姓と珍しい姓を表すために姓ごとの人数を決め、同じ世帯では姓を共有しやすくしました。RustのPolarsで、できた行から順に一定件数ずつ列形式のParquetに書き出します。[人口生成](src/population.rs)・[姓の割り当て](src/names.rs)

次の2行は生成した名簿の抜粋です。`birth_date` は1970年1月1日からの日数、`license_code` は保有者の架空の免許証番号で、未保有者の値は `NULL` です。

| `person_id` | `birth_date` | `surname_code` | `given_name_code` | `household_code` | `license_code` |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 14 | 8943 | 40417 | 904 | 399872545 | 275378698 |
| 15 | 14205 | 40417 | 717 | 399872545 | `NULL` |

14番と15番は姓も住所も同じです。2人とも過去の記録にいれば、この2項目だけではどちらかを決められません。基本実験では同じ事故に対し、氏名・メール・生年月日・世帯住所・免許証番号から照合に使う項目を変え、何も使わない場合を含む32通りを比較します。

## 登録者を選び、漏えい事故を作る

同じ人口から登録者を重複なしで一度抽出し、「Aだけ」「AとBの両方」「Bだけ」の3群に分けて2社の名簿を作ります。発表の条件ではA・Bにそれぞれ人口の25%が登録し、Bの登録者の半数はAにも登録します。その共通登録者の半数が両社で同じメールを使います。したがって、Bの登録者のうち、過去のAの記録とメールが一致し得るのは全体の25%です。[登録者の抽出](src/incidents/sampling.rs)・[メールの割り当て](src/incidents/registrations.rs)

漏えいする人は、過去の事故ではAの名簿から、新規の事故ではA・Bそれぞれの名簿から抽選します。Rustの `rand::seq::index::sample` による非復元抽出なので、1件の事故に同じ人が2回入ることはありません。事故ごとに独立に引き直すため、別の事故には同じ人が再登場することがあります。`rand_chacha` の乱数列を事故ごとに分け、同じシードで過去の事故を1件増やしても、それまでの事故と新規の対象者を再現できるようにしています。[事故生成](src/incidents.rs)

新規事故で漏れる機微情報は、架空の健診判定 `health_code` です。登録者ごとに `0`、`1`、`2` のいずれかを等確率で一度だけ割り当てるので、同じ人がA・Bの両方に登場しても値は一致します。個人を照合するための保存項目をメールだけに設定すると、新規の漏えい表に出るのは `row_id`、`mail_code`、`health_code` の3列です。[漏えい表の出力](src/incidents/output.rs)

## DuckDBで本人を予測し、正解表で採点する

例えば新規の漏えい表に `mail_code = 314`、`health_code = 2` という行があるとします。過去の記録でメール `314` に対応する既知の人物が1人なら、その人の健診判定は `2` と推定できます。実装では次の順で、本人の予測と答え合わせを分けています。

1. **過去の記録から候補を数える。** `matching` の過去の漏えい表と、`identity` の本人判明済みの行を、事故名と `row_id` で結合します。照合に使う値の組み合わせごとに `count(DISTINCT identity_token)` を計算するので、同じ人が3件の事故に出ても候補は1人です。
2. **新規の各行について予測する。** メール照合なら `mail_code` で候補を引き、候補が1人の行にだけその人物のトークンを付けます。候補が0人か複数人なら保留します。`health_code` はここで本人に結び付く値で、照合条件には使いません。
3. **予測を書き出してから採点する。** `scoring` に分けた正解の `person_id` と突き合わせ、正答・誤特定・保留の人数を数えます。「100人中何人が正答したか」と「100人全員が正答した試行が何回あったか」を別々に集計します。[照合・採点のSQLを組み立てるRustコード](src/evaluation.rs)

DuckDBを使うと、Rustが書いたParquetをデータベースに取り込まず、そのままSQLで読めます。Parquetは列ごとに値を保存するため、メールで候補を数えるときは、住所や免許証番号の列を読み飛ばせます。また、過去の記録を照合項目ごとに先に集計しておけば、同じメールが何度登場しても、新規の1行に過去の行をすべて結合する必要がありません。

## 全国規模の反復実験では、各人の最小順位だけを残す

メールが一人ひとりに固有という設定を利用して、メールのみ・氏名とメール・全5項目の3条件で反復実験を高速化しました。これらの条件では、新規の対象者が過去の事故に一度でも入ったかを判定できれば、過去の漏えい表を毎回作らずに済みます。Aの登録者を事故ごとに無作為に並べたと考えると、漏えい人数が `h` 人なら、漏れるのは順位 `0` から `h - 1` の人です。実装では、新規の対象者のうちAに登録している人の順位だけを重複なしで引きます。

```rust
let ranks = index::sample(rng, service_size, self.eligible_count);
for (person, rank) in self.people.iter_mut().zip(ranks) {
    person.best_past_rank = person.best_past_rank.min(rank);
}
```

たとえば、ある人の順位が過去3件で `8, 2, 5` なら、残す値は `2` だけです。各事故で3人漏れる条件なら、この人は2件目で漏れています。どの事故でも1人しか漏れない条件なら、一度も漏れていません。同じ抽選結果を使って、漏えい人数だけを変えた比較ができます。[反復実験のRust実装](examples/boundary_study.rs)

予備実験ではAの登録者を人口の25%、過去1件で漏れる人数を人口の6%と置きました。登録者を分母にすると `6 ÷ 25 = 0.24` なので、本実験では1件当たりの漏えい率を24%と、その半分の12%で比較しました。過去の本人対応がすべて判明している条件で、Aの新規100人をメールで全員正答した試行は、24%・過去24件で349/400回、12%・過去51件で341/400回でした。それぞれ、全員正答確率の95% Wilson信頼区間の下限が初めて80%以上になった測定点です。[予備実験](docs/ローカル予備実験.md)・[反復実験の結果](docs/全員正答確率の反復実験.md)

## 複数サービスの実験はRubyで厳密に計算する

追加実験では、新規サービスの登録者1万人を1,000人ずつ10群に分け、過去の各社に1群ずつ順番に割り当てました。11社目の名簿は1社目と同じですが、漏れる人は各社が独立に抽選します。各人が自分専用のメールを全社で使い、過去に漏れたメールの持ち主は判明していると仮定します。社数を増やすほど、これまで漏れなかった人のメールも過去の記録に載る機会が増えるため、新たに抽出した10人を全員特定できる確率が上がります。

Rubyでは、指定した人の全員が過去の記録に少なくとも1回は登場する確率を、群ごとに包除原理で求めます。各群から選ぶ人数の合計が10人になるように結果を組み合わせ、組合せ数と標準の `Rational` 型を使って、丸める前の分数を `4/5` と比較します。この名簿の割り当てで初めて80%に届いたのは、各社から240人ずつ漏れる場合は140社、120人ずつなら299社でした。[Rubyの厳密計算](scripts/multiservice-balanced.rb)・[Rustによるシミュレーション](examples/multiservice_leaks.rs)・[多サービス実験の結果](docs/多サービス実験結果.md)
